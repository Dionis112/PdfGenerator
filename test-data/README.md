# Тестовые данные

Корпус синтетический и не содержит производственных данных.

- [`altova/README.md`](altova/README.md): 21 пара XML/XSLT, 36 функций Altova (46 сигнатур), профили старого и современного движков, диаграммы, XBRL, даты и негативные сценарии; манифест и порядок снятия эталонов.

- `basic/input.xml` и `basic/document.xsl`: кириллица, XSLT 2.0 (`for-each-group`, `current-group`, `string-join`, суммы) и относительный `xsl:include`.
- `basic/expected.fo`: ожидаемая XML-структура FO, подтверждённая запуском SaxonCS-HE на Windows и Linux. Проверяются элементы, атрибуты и значимый текст, а не форматирование сериализации.
- `basic/empty.xml`: FO с заголовком «Пустой документ» без строк категорий.
- `basic/invalid.xml`: ошибка без замены предыдущего результата.
- `PngFixture.cs`: детерминированный RGBA PNG с непрозрачной и полупрозрачной половинами; может включать некорректный ICC и его CRC. Используется тестами и Demo.
- `sales/`: адаптированный MIT-корпус AltovaGen: отчёт по четырём товарам, версии XSLT 1.0/2.0, суммы строк и общий итог, кириллица, колонтитул и пустой отчёт. Оба шаблона выполняются нашим Saxon и проходят рендеринг PDF внутри процесса и через worker. Источник и лицензия указаны в [sales/README.md](sales/README.md).

Docker self-test получает библиотеку через готовый NuGet, выполняет полную цепочку до PDF и проверяет PNG/ICC и SVG. Результаты записываются в `artifacts/` или указанный каталог `--output`.

Этот корпус проверяет базовое поведение библиотеки. Совместимость производственных шаблонов требует собственного набора эталонных документов.
