Строгая приёмка включает шесть общих и три отрицательных сценария: без кэша, с холодным кэшем и повторно с общим executable, отдельно XDM и настоящий worker. Отрицательные evaluate проверяются на Transform/XPST0003, XPST0008, XPST0081. Неизвестная функция не является успехом отрицательного примера. Четыре банковских входа — базовый, конец месяца, пустые услуги, второй клиент — проверяются в обоих режимах с кэшем и без него. Итог: 54 проверки общего корпуса и 16 банковских проверок. В Windows один полный строгий прогон занял 29,26 с; это наблюдение на синтетическом корпусе, не производственный бюджет.

Банковский результат содержит три страницы. Проверены все 12 номеров платежей, даты, суммы строк и итогов, 78 000 руб. процентов, 1 278 000 руб. платежей, выбранные услуги, данные клиента и удаление повторных примечаний. Worker проверяет числовые ожидания внутри трансформации до сериализации исходного FO. Дополнительные тесты проверяют параллельное исполнение, идентичность узлов, namespace/base URI, position/last, типы параметров, бюджеты XPath, чтение существующих запрещённых файлов и восстановление worker после принудительного завершения.

Выявлен дефект адаптера SaxonCS-HE 13.0.0: свойства DependsOnFocus/HasSideEffects не доходят до низкоуровневой реализации. Для включённого профиля отключены оптимизации; настройки и версия входят в идентичность шаблона и PdfProcessingProfile. Обычные шаблоны с выключенным профилем используют прежнюю конфигурацию.

## Воспроизведение

```powershell
./eng/verify.ps1 -DependencyFeed "$env:USERPROFILE/.nuget/packages"
./eng/format.ps1 -Check
dotnet run --project eng/PdfGenerator.TemplateValidation -c Release -- . artifacts/altova2012-new-run --strict-altova2012
docker build -t pdfgenerator-altova2012 .
docker run --rm --read-only --tmpfs /tmp:rw,noexec,nosuid,size=512m --network none --memory 2g --cpus 4 pdfgenerator-altova2012
```

Ожидания и допустимые отличия находятся в `test-data/altova/expected-properties.json`, уровень подтверждения и ссылки — в манифесте v2. `acceptance.json` содержит хэши всех include/import, версию профиля/движка и наблюдения; ненулевой exit code блокирует verify и Docker build.

## Оставшаяся приёмка по плану

Оригинальный AltovaXML не обнаружен в проверенных стандартных каталогах и COM-регистрациях. Подтверждённых сравнением с оригиналом сигнатур **0**: результаты Saxon не объявлены эталонами Altova. Диаграммы, XBRL, схемные типы и пользовательские функции XSLT внутри evaluate остаются вне реализованного профиля; этапы E/F требуют отдельных компонентов и эталонов. Производственные бюджеты времени/памяти и реальные обезличенные рабочие шаблоны ещё не предоставлены. Поэтому полная совместимость всех 16 сценариев AltovaXML 2012 не заявляется.
