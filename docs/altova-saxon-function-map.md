# Сопоставление функций Altova и SaxonCS

Актуально на 06.10.2026 для `altova2012-general-v1` и SaxonCS-HE 13.0.0. Общий профиль включается через `XmlFoOptions.Altova2012 = new()`. По умолчанию расширения отключены. QName определяется URI `http://www.altova.com/xslt-extensions`; префикс может быть любым.

## Реализованный общий профиль

| Функция | Арность | Поведение и границы |
|---|---|---|
| `evaluate` | 1–33 | Динамический XPath 2.0, параметры `$p1…$p32`, контекст узла/позиции/размера, статические namespaces/base URI/collation. Переменные и функции XSLT автоматически не наследуются. |
| `distinct-nodes` | 1 | Структурное сравнение `deep-equal`; сохраняет первый исходный узел каждой группы, порядок и идентичность узлов. |
| `generate-auto-number` | 4 | Отдельные серии по ID, целые произвольной точности и сброс при изменении группы. Состояние принадлежит преобразованию. |
| `reset-auto-number` | 1 | Удаляет серию; следующий вызов начинает с переданного start. Пустой результат — предварительный контракт. |
| `encode-for-rtf` | 3 | RTF-экранирование и Unicode. Обработка пробелов и точное написание escapes требуют сравнения с оригинальным Altova. |
| `get-temp-folder` | 0 | Контролируемый каталог задания; создаётся лениво и удаляется при завершении преобразования. Отличается от общего системного каталога Altova. |

Функции зарегистрированы как интегрированные C# расширения при `ALLOW_EXTERNAL_FUNCTIONS=false`; произвольные вызовы .NET/Java запрещены. Для профиля отключены оптимизации SaxonCS-HE 13.0.0, поскольку его адаптер не передаёт признаки зависимости от контекста и побочных эффектов.

Проверены 6 имён и 8 сигнатур исходного корпуса по документации, с изоляцией параллельных заданий, кэшем и worker. Подтверждённых сравнением с оригинальным Altova сигнатур **0**. Подробные контракты, лимиты и пример настройки находятся в [инструкции](altova-2012-implementation.md), результаты — в [отчёте приёмки](altova-2012-validation-2026-10-06.md).

## Функции вне текущего профиля

| Семейство | Состояние | Возможный перенос |
|---|---|---|
| XBRL: labels/footnotes | Не зарегистрировано; этап F плана | Подготовка данных или отдельный XBRL-компонент с проверкой таксономий. |
| Диаграммы и штрихкоды | Не зарегистрировано; этап E плана | Генерация SVG/PNG перед XSLT или отдельный компонент. |
| Современные расширения дат, включая `add-months-to-date` | Не входят в AltovaXML 2012 general | Стандартные `xs:date` и `xs:yearMonthDuration`, как в банковском примере 2012. |
| Пользовательские .NET/Java функции, `msxsl:script` | Произвольное выполнение запрещено | Перенос вычислений перед XSLT или явная реализация необходимых QName. |
| `xsl:function`, схемные типы и функции контекста XSLT внутри `evaluate` | Не поддержаны динамическим контекстом | Передача вычисленных значений через `$p1…$p32` или переработка шаблона. |

Стандартные XPath/XSLT-функции и пользовательские `xsl:function` в самом шаблоне обрабатываются Saxon в обычном порядке; ограничения последней строки относятся к динамическому `evaluate`. `distinct-values()` не заменяет `distinct-nodes()`: оно сравнивает атомарные значения, а не структуру узлов.

## Проверка рабочих шаблонов

1. Проанализируйте главный XSLT и все include/import через `XsltDiagnostics` с включённым профилем и той же `LocalResourcePolicy`, что используется при запуске.
2. Сверьте URI, локальное имя и число аргументов с таблицей. Строки XPath в `evaluate` дополнительно проверяйте выполнением.
3. Выполните шаблон на эталонных XML, сравните FO/PDF с действующей системой, включая пустые данные, даты и параллельные задания.

Demo `--diagnose-xslt` анализирует обычный профиль без Altova. Для этого каталога используйте публичный API из [инструкции](altova-2012-implementation.md). Независимый `eng/audit-xslt-functions.ps1` остаётся вспомогательным инвентаризационным скриптом.

Версия предоставленной interop DLL 12.3.0.0 не устанавливает версию COM-сервера. Снятие оригинальных эталонов и оставшиеся этапы описаны в [плане совместимости](altova-2012-compatibility-plan.md).
