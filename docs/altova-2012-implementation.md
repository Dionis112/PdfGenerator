# Общий профиль AltovaXML 2012

06.10.2026. Реализован опциональный `altova2012-general-v1` на SaxonCS-HE 13.0.0. Проверки относятся к синтетическому корпусу и документации. Эталоны оригинального AltovaXML отсутствуют; версия interop DLL не подтверждает версию COM-сервера.

## Включение в приложении

Установите пакет по [инструкции README](../README.md#установка). Настройки передаются при создании преобразователя или worker и действуют для всех его заданий:

```csharp
using PdfGenerator;

var xmlOptions = new XmlFoOptions { Altova2012 = new Altova2012Options() };
using var transformer = new SaxonFoTransformer(xmlOptions);
await using var worker = new WorkerXmlPdfGenerator(xmlOptions: xmlOptions);
// PdfProcessingProfile.Create также принимает эти XmlFoOptions.
```

В DI укажите `services.AddXmlPdf(PdfExecutionMode.Worker, xmlOptions: xmlOptions)` либо `services.AddXmlPdf(xmlOptions: xmlOptions)` для InProcess. Для worker с ограничением времени используйте настройки из [раздела о worker](../README.md#5-выбор-режима-и-настройка-worker). Demo CLI не имеет переключателя профиля; банковский пример включается через публичный API или встроенный self-test.

По умолчанию `Altova2012 == null`: прежнее поведение сохранено. QName определяется URI `http://www.altova.com/xslt-extensions`, префикс произволен. `XsltDiagnostics(altova2012: xmlOptions.Altova2012)` использует тот же каталог и учитывает арность; DI передаёт профиль автоматически. `AnalyzeFile(path, resourcePolicy)` согласует разрешённые include/import с запуском.

## Перенос существующего шаблона

1. Скопируйте главный XSLT вместе со всеми `xsl:include`/`xsl:import` и ресурсами, сохранив относительные пути. Передавайте абсолютные пути XML/XSLT; каталоги зависимостей разрешите через `LocalResourcePolicy` в `ConversionRequest`.
2. Выполните `new XsltDiagnostics(altova2012: xmlOptions.Altova2012).AnalyzeFile(xsltPath, resourcePolicy)`. Проверьте QName, число аргументов, ошибки чтения модулей и неподдержанные функции. Статический статус `Supported` подтверждает наличие функции; строковый XPath внутри `evaluate` требует проверки выполнением.
3. Убедитесь, что результат шаблона — `fo:root`. Общие примеры корпуса, возвращающие обычный XML, проверяются отдельным стендом; публичный `SaxonFoTransformer` предназначен для FO.
4. Выполните преобразование с нужными типизированными параметрами. В `evaluate` передавайте параметры дополнительными аргументами как `$p1…$p32`: переменные XSLT автоматически не наследуются.
5. Сравните FO и PDF с результатом действующей системы: суммы, даты, порядок/повторы узлов, нумерацию, страницы и расположение блоков. Повторите на пустом вводе, границах дат и параллельных заданиях в нужном режиме.

Рабочий трёхстраничный пример — [код в README](../README.md#10-шаблоны-altovaxml-2012) и `test-data/bank-signing/bank-altova-2012.xsl`. Для него достаточно разрешить каталог `bank-signing`; главный шаблон импортирует соседний `bank-standard.xsl`.

## Поддерживаемые функции

| Функция | Арность | Контракт |
|---|---|---|
| `distinct-nodes` | 1 | `deep-equal` с default collation; первый исходный узел каждой группы, порядок и идентичность сохранены. |
| `evaluate` | 1–33 | XPath 2.0, типизированные `$p1…$p32`, исходные узлы; namespace/default element namespace, base URI, collation, текущий узел, position/last. Доступны стандартные XPath-функции и каталог Altova, включая вложенный evaluate. |
| `generate-auto-number` | 4 | Целые произвольной точности, отдельные ID, сброс при изменении группы, включая A→B→A; отрицательный и нулевой шаг. Состояние только на преобразование. |
| `reset-auto-number` | 1 | Удаляет серию; следующий вызов начинает с переданного start. Пустая последовательность результата — предварительный контракт до снятия оригинального эталона. |
| `encode-for-rtf` | 3 | Экранирование скобок и обратной косой черты, Unicode через знаковые UTF-16 `\uN?`, включая суррогатные пары. При сохранении: пробел `\u32?`, TAB `\tab `, перенос `\line `. CRLF — один перенос. Без сохранения пробельные серии сжимаются. Пустой ввод даёт пустую строку. Написание escapes и обработка пробелов предварительны до сравнения с Altova; RTF-рендерер не добавлен. |
| `get-temp-folder` | 0 | Существующий абсолютный путь отдельного задания с завершающим разделителем. Стабилен внутри задания, создаётся по необходимости и удаляется при завершении преобразования, включая ошибку. Это ограничение окружения, а не общий системный каталог Altova. |

Реализованы 6 имён и 8 сигнатур текущего корпуса, 6 положительных и 3 отрицательных сценария. Подтверждённых сравнением с Altova сигнатур пока **0**. Банковский `bank-altova-2012.xsl` использует четыре исходных расширения и стандартные даты XSLT 2.0. `bank-altova.xsl` остаётся смешанным современным профилем с неподдержанным `add-months-to-date`.

## Лимиты и ограничения

`evaluate` не наследует переменные XSLT: передавайте их дополнительными аргументами. Пользовательские `xsl:function`, схемные типы, `current()`, key/current-group и другие функции контекста XSLT не заявлены. Динамические `doc`, `collection`, `unparsed-text`, произвольные .NET/Java-вызовы и `xsl:result-document` запрещены. `ALLOW_EXTERNAL_FUNCTIONS=false` сохраняется; зарегистрированные интегрированные функции работают при этой настройке. Диагностики сохраняют безопасные коды, этап и позицию.

По умолчанию: 16 384 символа одного выражения, 1 024 вызова evaluate, глубина 16, 128 кэшированных XPath и 262 144 суммарных символа на преобразование. Настройки — в неизменяемом `Altova2012Options`. Кэш XPath принадлежит заданию; привязки параметров и результаты не разделяются. Это количественные бюджеты, не жёсткий timeout синхронного Saxon. Для timeout используйте worker.

Настраивайте бюджеты по числу фактических вызовов в вашем шаблоне:

```csharp
var xmlOptions = new XmlFoOptions
{
    Altova2012 = new Altova2012Options
    {
        MaxExpressionCharacters = 16_384,
        MaxEvaluations = 1_024,
        MaxEvaluationDepth = 16,
        MaxCachedExpressions = 128,
        MaxTotalExpressionCharacters = 262_144
    }
};
```

Все значения должны быть положительными; максимальная глубина не выше 64. Превышение бюджета не выключает ограничения и не вытесняет выражения из кэша: преобразование завершается ошибкой `FOER0000` на этапе Transform.

Прототип выявил дефект **SaxonCS-HE 13.0.0**: низкоуровневые `dependsOnFocus()` и `hasSideEffects()` возвращают false и не являются virtual, несмотря на свойства полного .NET API. В профиле выставлено `OPTIMIZATION_LEVEL=0`, иначе evaluate и автонумерация выносятся из циклов. Проверены циклы, cold/warm cache, группы, параллельные задания и worker. Неиспользуемые ленивые переменные не гарантируют побочных эффектов: сброс и выдача номеров должны участвовать в выполняемом шаблоне. После обновления Saxon повторите прототип перед включением оптимизаций.

Версия реализации, настройки и режим оптимизатора входят в ключ шаблона; XmlFoOptions входят в версию PdfProcessingProfile. Worker получает те же настройки и сверяет идентичность движка с версией каталога.

Диаграммы, XBRL, штрихкоды, пользовательские .NET/Java-функции и современные расширения дат пока не зарегистрированы. Этапы E/F и требования оригинальных эталонов остаются в [плане](altova-2012-compatibility-plan.md).

Источники контрактов: [AltovaXML 2012](https://www.altova.com/documents/2012/AltovaXMLRep.pdf#page=148) и [полный API Saxon 13](https://www.saxonica.com/html/documentation13/extensibility/extension-functions-CS/ext-fns-N.html). Typed `XsltParameter` и `ConversionRequest` уже реализованы.

## Проверка и разбор ошибок

Из корня исходников выполните отдельную строгую приёмку, каждый раз в новый каталог:

```powershell
$run = Join-Path 'artifacts/altova2012-acceptance' ([Guid]::NewGuid().ToString('N'))
dotnet run --project eng/PdfGenerator.TemplateValidation -c Release -- . $run --strict-altova2012
```

Ожидаются 70 проверок, ноль ошибок и файл `acceptance.json`. Полный `./eng/verify.ps1` дополнительно проверяет тесты, упаковку, потребителя NuGet и publish. [Порядок проверок](testing.md) и [подтверждённые результаты Windows/Linux](altova-2012-validation-2026-10-06.md).

| Наблюдение | Что проверить |
|---|---|
| Compile / `XPST0017` | Профиль включён на используемом экземпляре; правильные URI и арность; функция входит в каталог. |
| Transform / `XPST0003` | Синтаксис строки динамического XPath. |
| Transform / `XPST0008` | Переменные `$p1…$p32` и переданные аргументы `evaluate`. |
| Transform / `XPST0081` | Префиксы и пространства имён в месте вызова `evaluate`. |
| Transform / `FOER0000` | Бюджеты выражений и число вызовов; детали в диагностике преобразования. |
| Ошибка ресурса или чтения include/import | Полный комплект модулей, base URI и разрешённые каталоги. |
| XML вместо FO | Подходящий FO-шаблон: `bank-altova-2012.xsl`, а не общий XML-пример корпуса. |

После обновления Saxon или изменения шаблонов повторяйте строгую приёмку и сравнение собственных документов. Отчёт по синтетическому корпусу не заменяет эталоны вашей действующей системы.
